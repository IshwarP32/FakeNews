# Verification Methodology

The application does not cache searches or verdicts. Each analysis performs a
fresh search, but it follows the same rules so repeated analyses of the same
claim are comparable.

## Process

1. Normalize whitespace in the pasted headline and article text.
2. Ask Gemini for up to three PTI queries and three UNI queries.
3. Search only the queries generated by Gemini. The original headline is not
  sent directly to PTI or UNI search.
4. Run every generated query against the corresponding source search.
5. Resolve results to direct PTI or UNI pages and extract their metadata/text.
6. Remove duplicate articles and sort evidence by publication date, title, and
   URL before sending it to Gemini.
7. Ask Gemini to apply the fixed verdict rules below.

## Verdict Rules

- **True:** At least one source directly supports the main claim and no fetched
  source contradicts an important part.
- **False:** The evidence directly contradicts the claim or reports a materially
  different event, person, place, date, or number.
- **Partially True:** The central event is supported, but an important detail is
  wrong, exaggerated, or missing.
- **Unverified:** Evidence is missing, vague, or does not directly address the
  claim.
- **No evidence:** The application returns `Unverified` with `Low` confidence
  without asking Gemini to make a judgment.
- Conflicting PTI and UNI reports are explained, not averaged.
- A corrected story must contain only facts present in the fetched evidence.
- High confidence requires direct evidence; otherwise confidence is Medium or
  Low.

Gemini requests use temperature `0`. This reduces variation but cannot guarantee
identical answers when live websites publish new information between requests.
